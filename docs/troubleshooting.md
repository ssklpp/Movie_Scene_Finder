# 오류·버그 이력

Movie Scene Finder를 만들면서 생긴 오류, 버그, 운영 문제와 해결 방법을 모았다(2026-10-04 ~ 10-05).
근거는 커밋 본문, `CLAUDE.md` 구현 메모, 작업 기록이다. 해결 커밋이 있으면 함께 적었다.

같은 증상을 다시 만나면 **증상**으로 찾고 **해결**을 따른다. 아직 남은 문제는 마지막 절에 있다.

## 데이터 파이프라인

### s04 캡셔닝 중 9%가 429로 실패

- **증상**: 전체 캡셔닝을 시작하자 처음 400장 중 30장(약 9%)이 `429 Rate limit`으로 실패했다.
- **원인**: 계정의 `gpt-6-luna` 한도가 분당 20만 토큰(TPM)이다. OpenAI는 요청마다
  "입력 + `max_completion_tokens`"를 미리 차감하는데, 동시 요청 8개와 출력 한도 2,000으로는
  실제 사용량보다 훨씬 많이 차감됐다.
- **해결**: 출력 한도를 실측 평균(254토큰)에 맞춰 2,000 → 1,200으로 줄이고 동시 요청을 3개로
  낮췄다. 남은 3,484장이 실패 없이 끝났다(약 62분, $1.02).
- **커밋**: `e776fb9`

### pHash 중복 기준 8로는 거의 걸러지지 않음

- **증상**: 4,446장 중 4,242행이 남아 중복 제거 효과가 거의 없었다.
- **원인**: TMDB backdrop에는 같은 장면을 자르고, 확대하고, 색 보정한 사본이 많다.
  SPEC의 해밍 거리 8로는 이런 사본을 같은 장면으로 보지 못한다.
- **해결**: 기준을 20으로 올려 3,852행이 됐다(SPEC과 다르게 정한 값, `CLAUDE.md`에 기록).

### s05 캡션 검증의 오탐 7건

- **증상**: 캡션에 인물 이름이 들어갔다는 검사에서 7장(0.18%)이 실패했다.
- **원인**: 모두 오탐이다. 영화 「마이클」 출연진 이름 일부가 "마이크"와 같고, 「에이리언」의 영어
  제목 "Alien"이 일반 단어 "외계인"과 겹친다.
- **해결**: 목표(< 2%) 안이라 그대로 두었다. 한 글자 예명("비")은 날씨와 겹쳐 검사에서 뺐다.

### s08이 클라우드 적재를 건너뛸 수 있었음

- **증상**: 로컬 Qdrant에 적재한 뒤 `QDRANT_URL`을 클라우드로 바꿔 s08을 돌리면 "이미 처리함"으로
  건너뛸 수 있었다.
- **원인**: s08의 완료 기록(입력 parquet 기준)에 적재 대상 주소가 없었다.
- **해결**: 완료 키에 `QDRANT_URL`을 넣어 로컬과 클라우드에 각각 적재되게 했다.
- **커밋**: `4802187`

### SQLAlchemy 2.1 경고

- **증상**: s03, build_user_dict 실행 중 `SADeprecationWarning`이 나왔다.
- **원인**: SQLAlchemy 2.1에서 `Result.tuples()`가 deprecated됐다.
- **해결**: `.all()`로 바꿨다. 동작은 같다.
- **커밋**: `f4f2adb`

### 배포 backend에 Kiwi 사용자 사전이 없음

- **증상**: 배포 이미지에 사용자 사전이 빠져, 질의 토큰화가 색인(s07)과 달라질 수 있었다.
- **원인**: 사전이 git과 배포에서 빠지는 `pipeline/data/`에 있었다.
- **해결**: 사전을 `backend/app/search/data/user_dict.txt`로 옮겨 저장소에 넣었다.
  sparse 토큰화는 인덱싱과 질의가 반드시 같아야 하므로, 사전을 바꾸면 s07·s08을 다시 돌린다.
- **커밋**: `f3e2b9c`

## 로컬 VLM(vLLM)

모두 RTX 4060 8GB + WSL2 환경 문제다. 최종 캡션 모델은 `gpt-6-luna`로 정해 로컬 VLM은 비교용으로만 남았다.

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 원본 `Qwen3-VL-4B-Instruct`가 뜨지 않음 | 모델 8.9GB가 VRAM 8GB에 들어가지 않음 | AWQ 4비트 양자화본(`cyankiwi/Qwen3-VL-4B-Instruct-AWQ-4bit`) 사용 |
| 공식 FP8본 시작 중 WSL이 재시작됨 | 최대 길이를 3,072로 줄여야 할 만큼 메모리가 빠듯함 | FP8 대신 AWQ 4비트 사용(SPEC 설정 4,096, 0.85 그대로 뜸) |
| FlashInfer JIT 컴파일 실패 | WSL에 CUDA 툴킷(nvcc)이 없음 | `VLLM_USE_FLASHINFER_SAMPLER=0`, `--kv-cache-dtype fp8` 미사용(`scripts/run_vlm.sh`) |
| VRAM이 조금 모자람 | Windows 화면 표시와 브라우저·Discord·Steam이 VRAM을 씀 | 해당 프로그램을 끄면 약 0.5GB 확보 |
| 캡션에 프롬프트 예시 문구가 섞임("단발머리 소녀", "거인"), 단어 깨짐("캐노eing") | 4비트 소형 모델의 한계 | E2 비교 후 `gpt-6-luna`로 결정 |
| CapRL-Qwen3VL-4B를 비교하지 못함 | 9.7GB이고 vLLM용 양자화본이 없음 | E2 비교 대상에서 제외 |

## OpenAI API

### `gpt-6-luna`가 `max_tokens`·`temperature`를 거부

- **증상**: 요청이 파라미터 오류로 실패했다.
- **원인**: 추론 모델이라 두 파라미터를 받지 않는다. `reasoning_effort`는 `minimal`을 거부하고 `none`은 받는다.
- **해결**: `reasoning_effort`와 `max_completion_tokens`로 호출한다(캡션 low, 에이전트 rewrite·verify none).

### strict 구조화 출력이 자유 키 dict를 거부

- **증상**: rewrite의 `soft_filters: dict[...]` 스키마를 OpenAI strict 모드가 받지 않았다.
- **해결**: LLM에서는 고정 필드(`SoftFilterFields`)로 받고, 형식이 틀린 값은 코드에서 버린다(SPEC §7.1에 기록).

### 크레딧 소진으로 로컬과 배포가 함께 중단 (2026-10-05)

- **증상**: 이미지 평가가 `429 insufficient_quota (credit_balance_exhausted)`로 멈췄다. 같은 키를 쓰는
  배포 사이트도 검색이 "검색 중 오류가 났어요"로 끝났다.
- **원인**: 계정 크레딧이 바닥났다. 충전 후에도 로컬은 약 2분 뒤에야 반영됐고, 배포 서버는
  계속 429였다. 배포 backend의 키가 충전한 조직과 다른 것으로 보였다.
- **해결**: 크레딧 충전 뒤 OpenAI 키를 새로 발급해 `.env`와 Railway 변수 `OPENAI_API_KEY`를 모두 바꿨다.
  배포 오류의 원인은 LangSmith 추적(`retrieve`, `ChatOpenAI` 노드의 `RateLimitError`)에서 확인했다.
- **교훈**: 크레딧이 떨어지면 서비스도 함께 멈춘다. OpenAI 월 예산 한도와 잔액 알림을 함께 둔다.

## 에이전트(LangGraph)

### 재개할 때마다 재질문 문장이 바뀜

- **증상**: 재질문에 답해 그래프를 재개하면 질문 문장이 다른 문장으로 바뀌었다.
- **원인**: LangGraph는 재개할 때 `interrupt()`가 있는 노드를 처음부터 다시 실행한다. 질문을 LLM으로
  만드는 코드가 같은 노드에 있어 LLM이 다시 불렸다.
- **해결**: SPEC의 clarify를 `ask`(질문 만들기)와 `clarify`(`interrupt()`와 답 반영) 두 노드로 나눴다.
  나중에 질문을 고정 문장으로 바꿨지만 구조는 유지한다.

### 체크포인트에서 상태가 복원되지 않음

- **증상**: 서버를 재시작한 뒤 재개하면 상태 속 pydantic 모델이 복원되지 않았다.
- **원인**: 직렬화기가 허용한 모듈만 복원한다.
- **해결**: 상태에 넣는 모델을 `agent/state.py`의 `STATE_MODELS`에 등록한다(`checkpoint.make_serde`).
  새 모델을 상태에 넣으면 여기에도 추가해야 한다.

### verify가 흔한 장면에 과신

- **증상**: "누군가를 쫓아가는 장면"에 영화 「추격자」를 0.88로 매겼다.
- **원인**: 후보 제목을 함께 주자, LLM이 제목 글자와 묘사의 겹침으로 점수를 올렸다.
- **해결**: verify 프롬프트에 "제목 글자로 점수를 올리지 말 것", "흔한 장면이면 0.5 이하"를 넣었다.

### 응답이 느림 (verify 출력 토큰, 추론 꼬리)

- **증상**: 첫 응답이 약 10초, 재질문마다 7~10초가 더 걸렸다(목표 p95 8초).
- **원인**: 요청 시간의 75%가 verify였고, 그 시간은 출력 토큰 수에 비례했다. rewrite도 가끔 추론을
  558~753토큰 써서 호출 하나가 8.3초 걸렸다.
- **해결**:
  - verify 출력에서 쓰지 않는 `evidence_scene_ids`를 빼고, reason을 상위 5편만 50자 이내로 줄였다(`1b4e44f`).
  - 서버 시작 때 Kiwi, 영화 목록, Qdrant, OpenAI 연결을 미리 준비한다(`agent/warmup.py`, 첫 요청 약 3초 단축).
  - 재질문 문장을 LLM 생성에서 고정 문장으로 바꿨다(`e1f9aff`).
  - verify와 rewrite의 추론을 껐다(`515322d`, `179d0ca`). 정확도 차이는 실행 간 흔들림 범위였다.
  - 배포 기준 첫 요청 중간값 4.2초, 최대 5.2초가 됐다.

### 사진 캡션이 실패하면 빈 질의로 검색 (2026-10-05)

- **증상**: 사진만 올렸는데 캡션이 실패하면(손상된 이미지, API 한도 등) "검색 중 오류가 났어요"로 끝났다.
- **원인**: 캡션 없이 rewrite로 넘어가고, rewrite마저 실패하면 빈 문자열을 임베딩에 보내
  `400 input cannot be an empty string`이 났다. rewrite가 성공해도 빈 입력에서 검색어를 지어낼 수 있었다.
- **해결**: 사진 분석 뒤 검색할 내용(텍스트 또는 캡션)이 없으면 그래프를 바로 끝내고,
  `image_unreadable` 오류로 "다른 사진을 올리거나 장면을 글로 적어 달라"고 안내한다.
  사진과 텍스트를 함께 보내면 텍스트로 검색한다. 손상된 PNG로 로컬과 배포에서 확인했다.
- **커밋**: `9c9b15f`

### 사진 질의가 느림 (2026-10-05)

- **증상**: 이미지 dev 에이전트 요청 p95가 13초대로 목표 8초를 넘었다.
- **원인**: 텍스트 질의 과정에 사진 캡션 단계(약 4초)가 더해진다.
- **시도 1**: 질의 캡션의 추론 끄기(`fa3994f`). 지연은 0.5~2초만 줄고 정확도가 조금 떨어져 채택하지 않았다.
- **해결**: 사진만 있는 질의는 rewrite LLM을 건너뛰고 캡션을 바로 검색어로 쓴다(`IMAGE_SKIP_REWRITE`).
  R@1은 흔들림 범위에서 같았고, 요청 중간값이 약 2.5초 줄었다(9.2 → 6.5초).
- **커밋**: `2ac37f4`, `b9da0d5`

## 배포·운영

### rate limit이 모든 사용자를 하나로 묶을 수 있었음

- **증상**: 플랫폼 프록시 뒤에서는 모든 요청이 프록시 IP 하나로 보인다.
- **해결**: uvicorn `--proxy-headers --forwarded-allow-ips='*'`로 `X-Forwarded-For`의 IP를 쓴다.
  클라이언트가 이 헤더를 꾸밀 수 있다는 한계는 OpenAI 월 예산 한도로 막는다.
- **커밋**: `2d15010`

### Railway `DATABASE_URL` 형식

- **증상**: Railway의 `postgres://` 주소로는 SQLAlchemy가 연결하지 못했다(psycopg2 없음).
- **해결**: `postgres://`·`postgresql://`을 `postgresql+psycopg://`로 바꿔 읽는다.
- **커밋**: `2d15010`

### Docker 이미지가 큼

- **증상**: backend 이미지가 1.99GB였다.
- **해결**: 2단계 빌드로 backend 의존성만 설치하고 uv와 캐시를 최종 이미지에서 뺐다(805MB).
- **커밋**: `2d15010`

### 배포 직후 결과에 썸네일이 비어 있음

- **증상**: R2 썸네일을 켠 직후 결과 화면에 근거 장면 썸네일이 보이지 않았다.
- **원인**: 배포 전에 시작한 검색 세션에는 `thumb_url`이 비어 있다.
- **해결**: 새로 검색하면 보인다(버그 아님).

### Postgres 재시작 후 첫 요청 실패 (2026-10-05)

- **증상**: 배포 DB의 TCP Proxy를 켜고 끈 직후 첫 검색 2건이 "검색 중 오류가 났어요"로 끝났다.
  LangSmith에는 `AdminShutdown: terminating connection due to administrator command`가 남았다.
- **원인**: Postgres가 재시작되면서 연결이 끊겼는데, LangGraph 체크포인터의 psycopg 연결 풀이
  연결을 확인하지 않고 끊긴 연결을 그대로 빌려줬다. 앱 DB(SQLAlchemy)는 이미 `pool_pre_ping`을 썼다.
- **해결**: 풀에 `check=ConnectionPool.check_connection`을 걸었다. 로컬에서 풀을 연 뒤 postgres
  컨테이너를 재시작해 재현했고, 수정 전 3회 모두 실패에서 수정 후 3회 모두 성공을 확인했다.
- **커밋**: `f58159c`

### 배포 DB 주소가 템플릿 그대로 보임 (2026-10-05)

- **증상**: Railway Variables의 `DATABASE_PUBLIC_URL`이 `postgresql://${{PGUSER}}:...@${{RAILWAY_TCP_PROXY_DOMAIN}}:...`로
  보였고, 복사하면 `...@:/railway`처럼 호스트와 포트가 비었다.
- **원인**: Variables 탭은 참조를 풀지 않은 템플릿을 보여 준다. TCP Proxy가 꺼져 있으면 도메인·포트 변수가 빈 값이다.
- **해결**: Postgres → Settings → Networking에서 TCP Proxy를 켜고, Connect → Public Network의 완성된 주소를 쓴다.
  재배포는 필요 없다. 쓰고 나면 TCP Proxy를 다시 끈다(`scripts/copy_catalog.sh`, `copy_eval_runs.sh` 참고).

## 평가

### 이미지 세트의 dev/test가 변형 종류별로 쏠림 (2026-10-05)

- **증상**: 이미지 dev 결과를 변형별로 나눠 보니 dev에 crop·crop_color만 있었다.
- **원인**: split을 번호 순으로 번갈아 주면서 변형 4종도 번호 순으로 돌려, 두 주기가 겹쳤다.
  dev에는 crop·crop_color만, test에는 color·degrade만 들어갔다. 테스트는 dev/test 전체 수만 확인했다.
- **해결**: split을 변형 종류 안에서 번갈아 주도록 바꾸고(종류별 dev 10 / test 10), 종류별 균형을
  확인하는 테스트를 넣었다. 잘못된 dev로 잰 run 29·30은 지웠다. test는 아직 쓰지 않은 상태였다.
- **커밋**: `1b1ab9d`

### 모니터 촬영 사진의 파일 이름이 한 칸씩 밀림 (2026-10-05)

- **증상**: img-0093~0100 사진이 같은 번호의 원본과 다른 장면이었다.
- **원인**: 촬영이나 이름 붙이기 순서가 어긋나, 사진 N이 원본 N+1이었다(사진 100은 원본 93).
- **해결**: 사진과 원본을 작은 회색조 이미지로 줄여 상관을 비교해 짝을 찾고, 대조표로 눈으로도
  확인한 뒤 이름을 바로잡았다. 촬영본을 바꾸면 같은 대조를 다시 한다.

### 이미지 평가 결과가 synthetic 결과를 덮을 수 있었음 (2026-10-05)

- **증상**: `E1_hybrid` 설정을 `--datasets image`로 돌리면 같은 실험·설정 이름으로 기록돼,
  대시보드와 `eval.report`가 synthetic 결과 대신 이미지 결과를 "최신"으로 보여 줄 수 있었다.
- **해결**: 이미지 전용 설정(실험 이름 `IMG`)을 따로 두고, 대시보드를 실험·데이터셋·평가 방식별로 묶었다.
- **커밋**: `bfe799f`, `5124d6a`

### 평가 기록의 커밋 값에 `-dirty`가 붙음

- **증상**: `eval_runs`의 커밋 값이 `xxxx-dirty`로 남았다.
- **원인**: `backend`, `pipeline`, `eval`에 커밋하지 않은 변경이 있으면 붙는다. 새 설정 yaml을 커밋하기
  전에 평가를 시작한 경우도 해당된다.
- **해결**: 설정과 코드를 먼저 커밋하고 평가를 돌린다.

### dense 검색이 약함 (버그 아님)

- **증상**: E1에서 dense R@1이 0.100으로 sparse(0.210)의 절반이었다.
- **확인**: 저장 벡터, Qdrant 결과, 전수 계산 순위가 모두 일치해 파이프라인 문제가 아니었다.
  많이 바꿔 쓴 구어체 질의에서 `text-embedding-3-small`의 원문 장면 유사도가 비슷한 다른 장면보다 낮았다.
- **대응**: hybrid 검색과 에이전트의 질의 재작성·검증으로 보완했다.

## 개발 환경

### Git Bash curl이 한글 입력을 깨뜨림

- **증상**: 배포 API를 재면서 보낸 질의가 LangSmith에 `»ç¶÷µéÀÌ`처럼 깨져 보였다.
- **원인**: Windows(Git Bash) curl이 `-F "text=한글"`을 CP949 바이트로 보내고, 서버(Starlette)는
  UTF-8이 아니면 Latin-1로 읽는다.
- **해결**: 배포 API 측정은 WSL curl로 한다. 깨진 입력으로 잰 측정값은 버리고 다시 쟀다.
- **커밋**: `d04e1c4`

### WSL에서 브라우저 스크린샷을 찍을 수 없음

- **원인**: WSL에 Chromium 실행 라이브러리가 없다(설치에 sudo 필요).
- **해결**: Windows의 Node + `playwright-core` + Edge(`channel: "msedge"`)로 `localhost`를 캡처한다.
  포스터는 지연 로딩이라 스크롤해야 찍힌다.

### 파일 경로를 지정한 mypy가 엉뚱한 오류를 냄

- **증상**: `mypy --strict eval/xxx.py`처럼 파일을 지정하면 `app.*`에 `import-untyped` 오류가 쏟아졌고,
  그 뒤 `mypy backend pipeline`에서도 `Module "app.core" has no attribute "llm"`이 났다.
- **원인**: 파일을 지정하면 모듈 해석 경로가 달라지고, 그 결과가 `.mypy_cache`에 남는다.
- **해결**: CI와 같은 `uv run mypy backend pipeline`으로 돌리고, 이상하면 `.mypy_cache`를 지운다.

### 배포 DB 주소 파일이 만들어지지 않음

- **증상**: `echo '...' ~/.msf_deploy_db_url && chmod 600 ...`이 "No such file"로 끝났다.
- **원인**: `>`가 빠져 파일에 쓰지 않고 화면에 출력만 했다(비밀번호가 터미널에 노출됨).
- **해결**: `echo '...' > ~/.msf_deploy_db_url`처럼 리디렉션한다. 비밀 값은 화면에 출력하지 않는다.

### 배포 DB 주소 파일이 빈 파일로 저장됨 (2026-10-06)

- **증상**: `read -rs`(입력 숨김)로 붙여 넣어도, nano에 붙여 넣어도 `~/.msf_deploy_db_url`이 0바이트였다.
- **원인**: 클립보드에 주소가 없었다. Railway는 변수 값을 `*****`로 가려 두므로 화면의 글자를 드래그해서는
  실제 값이 복사되지 않는다.
- **해결**: Postgres 서비스 → Connect 탭 → Public Network의 Connection URL 옆 복사 아이콘으로 복사한다.
  붙여 넣은 뒤 `sed -E 's#//[^@]*@#//***@#' 파일`처럼 비밀번호를 가리고 내용을 확인한다.

### `pkill -f`가 자기 셸까지 종료함 (2026-10-06)

- **증상**: `wsl.exe -e bash -lc "pkill -f 'msf-repro'; ..."`가 뒤 명령을 실행하지 않고 exit 15로 끝났다.
- **원인**: `-f`는 전체 명령줄에서 패턴을 찾으므로, 그 패턴을 문자열로 품은 `bash -lc` 자신도 맞는다.
- **해결**: 프로세스를 끄는 명령과 나머지 명령을 따로 실행하거나, `pgrep -af`로 대상을 먼저 확인한다.

### 프로젝트 `.env`가 배포 Qdrant를 가리킴 (2026-10-06)

- **증상**: 새 환경 재현 준비 중, 프로젝트 `.env`의 `QDRANT_URL`이 Qdrant Cloud(배포)인 것을 발견했다.
- **위험**: 이 `.env`로 `make index`나 `s08`을 돌리면 배포 컬렉션의 alias `scenes`가 새 적재로 바뀌어
  서비스 검색 결과가 달라진다.
- **해결**: 재현은 `.env.example`에서 새로 만들고 키만 채웠다(`QDRANT_URL=http://localhost:6333`).
  로컬 실험을 할 때는 `QDRANT_URL`을 먼저 확인한다.

## 남은 문제

- **사진 질의 지연**: rewrite 생략 후에도 사진 test 요청 p95가 11.6초(순차, dev는 동시 4에서 9.5~10.4초)로
  목표 8초를 넘는다. 남은 시간은 사진 캡션(약 4초)과 verify다.
- **사람 질의 정확도**: test Recall@1 0.360, Recall@5 0.440으로 MVP 목표(0.40, 0.70)에 못 미친다.
  유형별 원인과 개선 방향은 README의 "실패 사례"에 있다.
- **rate limit 우회 가능성**: `X-Forwarded-For`를 꾸미면 제한을 피할 수 있다. Railway 프록시 대역을 알면
  그 대역만 믿도록 좁힌다.
- **배포 버전 확인 수단 없음**: backend에 버전 엔드포인트가 없어, 새 배포가 반영됐는지 밖에서 구분하기 어렵다.
  지금은 Railway Deployments 탭에서 확인한다.
